# Интернет по белому списку

**Rethink** фильтрует трафик на колонке через VPN-интерфейс Android. Если интернет нужен через внешний VPN, туннель поднимает **роутер**. Отдельного внешнего VPN на колонке в этой конфигурации нет. В сетях, где прямое подключение WireGuard не проходит, подключите колонку по Wi-Fi или Ethernet к роутеру с работающим VPN.

1. Пока настраиваете фильтр, держите колонку в сети без интернета. Для управления удобнее использовать USB ADB. Установите версию [Rethink](https://github.com/celzero/rethink-app) для Android 9. Разрешите приложению создать VPN и включите режим Firewall + DNS. Закройте доступ новым и неизвестным приложениям, а также пересмотрите уже выданные разрешения, включая системные пакеты. Затем добавляйте нужные приложения по одному.
2. В Android включите «Постоянный VPN» и «Блокировать соединения без VPN». В комплекте есть ярлык, который открывает настройки VPN, если этот экран доступен на прошивке. Если экран не открывается, проверьте настройки через приложение VPN и сверяйте состояние командами ниже.
3. На проверенной колонке поверх настроек Android действуют правила IPv4 и IPv6. Они применены с правами root. Прямой выход в сеть в обход TUN разрешён только самому фильтру. Несколько общих UID системных служб могут обращаться только к локальному интерфейсу. Сверяйте UID и интерфейсы на своей колонке. Если один UID принадлежит нескольким пакетам, разрешение затронет их все. APK из релиза эти правила не добавляют.
4. Проверьте запрет, затем разрешите доступ Spotify, Twitch, TizenTube и другим нужным приложениям. Для ассистента нужен доступ к OpenAI, для диктовки — к Groq, если вы её включили. Для Lampa откройте нужные сервисы и адрес своего сервера. Настройкам Android, Bluetooth и пульту для местной работы выход в интернет не нужен. Если Wi-Fi показывает «без интернета», проверьте DNS, маршрут и TLS. Системная проверка доступности интернета может быть заблокирована, даже когда разрешённые приложения работают.
5. Если колонка должна выходить в интернет только через VPN, настройте роутер так, чтобы при падении туннеля он закрывал ей доступ. Проверьте IPv4, IPv6 и DNS. Одного HTTP-прокси для этого недостаточно, поскольку приложения могут подключаться напрямую.

```sh
adb shell settings get secure always_on_vpn_app
adb shell settings get secure always_on_vpn_lockdown
adb shell pm list packages --user 0 -U
adb shell ip route
adb shell ip -6 route
# Эти две команды выполняются в сеансе с правами root.
iptables -S OUTPUT
ip6tables -S OUTPUT
```

После загрузки проверены разрешение и повторная блокировка доступа обычного приложения. При остановке VPN доступ пропадал. Несколько системных UID не выходили в сеть по IPv4 и IPv6, но локальные ответы продолжали приходить. Разрешённое приложение установило TLS-соединение и получило HTTP 200. Повторите проверки на Wi-Fi и Ethernet. [Документация Android о VpnService](https://developer.android.com/reference/android/net/VpnService).

**Что ещё нужно проверить.** Полный запрет исходящего трафика от подачи питания до запуска защиты пока не подтверждён. Если запрет нужен с первой секунды, ограничьте выход колонки на роутере. После заводского сброса снова проверьте сетевые настройки и правила.
