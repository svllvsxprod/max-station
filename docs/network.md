# Интернет по белому списку

В рабочей схеме есть два уровня. **Rethink** использует локальный Android VpnService как фильтр на колонке. **Роутер** при необходимости ведёт разрешённый WAN через свой VPN. Эта реализация не включает поддерживаемую настройку WAN-туннеля на колонке. В сетях, где WireGuard напрямую не проходит, подключайте колонку по Ethernet или Wi-Fi к роутеру с уже работающим VPN. Сетевые условия зависят от провайдера.

1. Подготовьте изолированный сегмент без WAN, удобнее с проводным ADB для обслуживания. Установите версию [Rethink](https://github.com/celzero/rethink-app), совместимую с Android 9. Подтвердите разрешение Android на VPN, выберите режим Firewall + DNS, включите запрет неизвестным и новым приложениям. Сбросьте уже выданные широкие разрешения, включая системные пакеты. Открывайте конкретные приложения по необходимости.
2. В Android включите «Постоянный VPN» и «Блокировать соединения без VPN». Ярлык VPN в комплекте пытается открыть системный экран настроек. На прошивке с отсутствующим экраном проверьте доступность через штатное приложение настройки VPN, затем прочитайте фактическое состояние.
3. На рабочем экземпляре поверх Android lockdown применялись правила IPv4/IPv6 в авторизованной root-сессии. Они запрещали прямой выход вне TUN, кроме UID фильтра, и оставляли общие UID штатных служб только на loopback. Правила сверяли по фактическим UID и интерфейсам, не по названию пакета. При повторении не копируйте числовые UID из чужого устройства. UID может принадлежать нескольким пакетам. Допуск общего UID может пропустить весь этот набор. APK релиза не прописывают root-правила.
4. Включите разрешения на Spotify, Twitch, TizenTube и другие реально используемые клиенты только после проверки запрета. Для Max Station Voice разрешите необходимые OpenAI и, если выбран системный распознаватель, Groq API. Для Lampa открывайте используемые сервисы и адрес своего сервера. Оставьте доступ к Android-компонентам настроек, Bluetooth и пульта локальным. При проблеме с Wi-Fi сначала отличите статус «без интернета» из-за системной captive portal проверки от фактических отказов DNS, маршрута и TLS.
5. Для подключения к WAN ведите сегмент колонки через роутер с fail-closed правилом. Без туннеля WAN должен быть закрыт для устройства. Проверяйте отдельно IPv4 и IPv6. DNS и прямой трафик должны подчиняться той же политике. Не используйте HTTP-прокси как единственный барьер, поскольку приложения могут подключаться напрямую.

```sh
adb shell settings get secure always_on_vpn_app
adb shell settings get secure always_on_vpn_lockdown
adb shell pm list packages --user 0 -U
adb shell ip route
adb shell ip -6 route
# Следующие две проверки выполняются внутри уже авторизованной root-сессии.
iptables -S OUTPUT
ip6tables -S OUTPUT
```

На реальной колонке после загрузки проверили разрешение и повторный запрет обычного UID, отказ при остановке VPN, IPv4 и IPv6 для нескольких системных UID и сохранение локальных ответов. Разрешённое приложение получало проверенный TLS и HTTP 200. Отдельно проверьте отсутствие обхода при остановке фильтра и повторите измерения на Wi-Fi и Ethernet. Обычный VPN Android имеет ограничения, включая системный трафик. [Документация VpnService](https://developer.android.com/reference/android/net/VpnService).

**Граница проверки.** Для периода от подачи питания до старта Android/VPN и root-защиты не доказан полный запрет исходящих соединений UID 0 на обоих интерфейсах. Внешний закрытый сегмент во время запуска защищает эту границу независимо от приложений. Для непрерывного ограничения с момента питания контролируйте выход на роутере. Состояние рабочего профиля не гарантирует поведение после сброса.
